11.3 Custom C++ and CUDA Operators

Created Date: 2025-07-30

PyTorch offers a large library of operators that work on Tensors (e.g. torch.add, torch.sum, etc). However, you may wish to bring a new custom operator to PyTorch. This tutorial demonstrates the blessed path to authoring a custom operator written in C++/CUDA.

For our tutorial, we’ll demonstrate how to author a fused multiply-add C++ and CUDA operator that composes with PyTorch subsystems. The semantics of the operation are as follows:

def mymuladd(a: Tensor, b: Tensor, c: float):
    return a * b + c

The Python body is the specification. A custom C++ or CUDA operator is that specification registered so the dispatcher, autograd, and torch.compile can see it. The previous chapter wrapped a Python function. This one moves the same kind of operation into a native library. There is no mymuladd extension checked into this repository; the steps below are the path, and the reference implementation of the math stays the three-line function.

11.3.1 Register the schema

A schema names the operator and its arguments, for example mylib::mymuladd(Tensor a, Tensor b, float c) -> Tensor. The dispatcher uses that string. A Meta implementation returns an empty tensor of the right size so shape inference and torch.compile do not have to run the kernel. For mymuladd the output shape is the broadcast of a and b.

11.3.2 CPU and CUDA kernels

The CPU kernel walks the broadcast and writes out[i] = a[i] * b[i] + c. The CUDA kernel assigns one thread per output element and does the same arithmetic. Both register under the same schema, tagged with the device. A call on a CUDA tensor must hit the CUDA kernel; a silent copy back to CPU is the usual performance bug.

11.3.3 Autograd

The backward of a * b + c is ordinary calculus. The gradient with respect to a is grad_out * b, the gradient with respect to b is grad_out * a, and c is a float with no gradient. Register that formula or the operator will run in inference and fail as soon as a loss calls backward. After the native library loads, torch.ops.mylib.mymuladd is the call, and it should match a * b + c on a few random tensors before you trust it inside a model.
