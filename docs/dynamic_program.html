10.3 Dynamic Programming

Created Date: 2025-07-10

The term dynamic programming (DP) refers to a collection of algorithms that can be used to compute optimal policies given a perfect model of the environment as a Markov decision process (MDP). Classical DP algorithms are of limited utility in reinforcement learning both because of their assumption of a perfect model and because of their great computational expense, but they are still important theoretically.

We usually assume that the environment is a finite MDP. Its state, action, and reward sets \(\mathcal{S}\), \(\mathcal{A}\), and \(\mathcal{R}\) are finite, and the dynamics are the probabilities \(p(s', r \mid s, a)\). \(\mathcal{S}^+\) is \(\mathcal{S}\) plus a terminal state when the problem is episodic.

Although DP ideas can be applied to problems with continuous state and action spaces, exact solutions are possible only in special cases. A common way of obtaining approximate solutions for tasks with continuous states and actions is to quantize the state and action spaces and then apply finite-state DP methods.

Dynamic programming uses a value function to search for a good policy. Once \(v_*\) or \(q_*\) is known, the optimal policy is the greedy action in each state. Those two functions satisfy the Bellman optimality equations:

\(v_*(s) = \max_a \sum_{s', r} p(s', r \mid s, a)\,[r + \gamma v_*(s')]\)

10.3.1 Policy Evaluation (Prediction)

Policy evaluation computes \(v_\pi\) for a policy you already chose. Sweep every state and replace its value with the one-step backup. The terminal state stays at 0. Repeat until the largest change is tiny:

\(v_{k+1}(s) = \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a)\,[r + \gamma v_k(s')]\)

The check is a line of three states. Action "right" walks \(0 \to 1 \to 2\), and the only reward is \(1\) on the last step. With \(\gamma = 0.9\), the backup gives \(v(1) = 1\) and \(v(0) = 0.9\). File policy_eval.py asserts those two numbers. Run python 10_rl/3_dp/policy_eval.py.

10.3.2 Policy Improvement

Improvement looks at each state and keeps the action whose one-step return is larger. That return is what you would get by taking \(a\) once and then following \(\pi\):

\(q_\pi(s, a) = \sum_{s', r} p(s', r \mid s, a)\,[r + \gamma v_\pi(s')], \quad \pi'(s) = \arg\max_a q_\pi(s, a)\)

On the same line, a second action jumps from state 0 straight to the end. A jump reward of 0 loses to walking, because walking is worth \(0.9\). A jump reward of 2 wins, and evaluating the new policy sets \(v(0) = 2\). The script asserts both choices. Alternating evaluation and this greedy step is policy iteration. The next page, DQN, is the same idea when you no longer have \(p(s', r \mid s, a)\) written down and have to sample it.
