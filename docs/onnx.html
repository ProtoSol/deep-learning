12.1 ONNX

ONNX : Open Neural Network Exchange

Created Date: 2025-06-26

ONNX is an open format built to represent machine learning models. ONNX defines a common set of operators - the building blocks of machine learning and deep learning models - and a common file format to enable AI developers to use models with a variety of frameworks, tools, runtimes, and compilers.

12.1.1 Build Model

Building an ONNX model primarily involves defining a computational graph using ONNX operators and then serializing it into the ONNX format. While you typically train a model in a framework like PyTorch or TensorFlow and then export it to ONNX, you can also construct an ONNX graph directly using the onnx Python library.

      12.1.3 Inference using ONNX

      The flower script scores images before the export, and it scores them with PyTorch. It torch.saves the whole module to flower_conv_mlp.pth, loads that file back, and runs three sample photos from class folders 54, 43, and 32 through transform_val.

      ONNX inference would load flower_conv_mlp.onnx in a runtime, bind a float tensor to the name input with the traced shape, and read the logits named output. flower_conv_mlp.py returns after torch.onnx.export. No InferenceSession appears anywhere in the repo, so there is no numeric comparison between the ONNX graph and the .pth module.

      12.1.4 Export to Another Framework

      An ONNX file is a graph of standard ops plus the trained initializers, so another framework can rebuild the same conv net from the file alone. The direct-construction listing above is that graph spelled by hand: tensor value infos, MatMul and Add nodes, make_graph, and make_model.

      flower_conv_mlp.py produces the PyTorch side of the handoff and stops at flower_conv_mlp.onnx. It does not import that file into TensorFlow or any other training framework. The artifacts it does leave are the trained convmlp_s weights, the .pth snapshot, and one named-input ONNX graph.
