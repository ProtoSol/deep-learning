10.5 PPO

Reinforcement Learning (PPO) with TorchRL Tutorial

Created Date: 2025-06-19

This tutorial demonstrates how to use PyTorch and torchrl to train a parametric policy network to solve the Inverted Pendulum task from the OpenAI-Gym/Farama-Gymnasium control library.

Edan Meyer's Proximal Policy Optimization Explained is the picture for this page. John Schulman's bootcamp lecture is Natural Policy Gradients, TRPO, PPO.

Proximal Policy Optimization (PPO) is a policy-gradient algorithm where a batch of data is being collected and directly consumed to train the policy to maximise the expected return given some proximality constraints. You can think of it as a sophisticated version of REINFORCE, the foundational policy-optimization algorithm. For more information, see the Proximal Policy Optimization Algorithms paper.

PPO is usually regarded as a fast and efficient method for online, on-policy reinforcement algorithm. TorchRL provides a loss-module that does all the work for you, so that you can rely on this implementation and focus on solving your problem rather than re-inventing the wheel every time you want to train a policy.

For completeness, here is a brief overview of what the loss computes, even though this is taken care of by our ClipPPOLoss module—the algorithm works as follows:

  1. we will sample a batch of data by playing the policy in the environment for a given number of steps.

  2. Then, we will perform a given number of optimization steps with random sub-samples of this batch using a clipped version of the REINFORCE loss.

  3. The clipping will put a pessimistic bound on our loss: lower return estimates will be favored compared to higher ones.

The precise formula of the loss is the clipped surrogate. With the probability ratio \(r_t(\theta) = \pi_\theta(a_t|s_t) / \pi_{\theta_{\mathrm{old}}}(a_t|s_t)\) and the advantage \(A_t\),

\(L^{\mathrm{CLIP}}(\theta) = \mathbb{E}_t\left[\min\big(r_t(\theta) A_t,\; \mathrm{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\, A_t\big)\right]\)

There are two components in that loss: in the first part of the minimum operator, we simply compute an importance-weighted version of the REINFORCE loss (for example, a REINFORCE loss that we have corrected for the fact that the current policy configuration lags the one that was used for the data collection). The second part of that minimum operator is a similar loss where we have clipped the ratios when they exceeded or were below a given pair of thresholds.

This loss ensures that whether the advantage is positive or negative, policy updates that would produce significant shifts from the previous configuration are being discouraged.

This tutorial is structured as follows:

  1. First, we will define a set of hyperparameters we will be using for training.

  2. Next, we will focus on creating our environment, or simulator, using TorchRL’s wrappers and transforms.

  3. Next, we will design the policy network and the value model, which is indispensable to the loss function. These modules will be used to configure our loss module.

  4. Next, we will create the replay buffer and data loader.

  5. Finally, we will run our training loop and analyze the results.

Throughout this tutorial, we’ll be using the tensordict library. TensorDict is the lingua franca of TorchRL: it helps us abstract what a module reads and writes and care less about the specific data description and more about the algorithm itself.

The script that follows this outline is simple_ppo.py. It trains on InvertedDoublePendulum-v4 for 50,000 frames, enough to see the return move, and the comment in the file says a full run is closer to one million frames.

10.5.1 Define Hyperparameters

The network width is num_cells = 256. The optimizer is Adam at 3e-4, with gradients clipped to norm 1.0. Data comes in batches of frames_per_batch = 1000, and each batch is optimized for num_epochs = 10 passes over minibatches of 64. The clip range is clip_epsilon = 0.2, which is \(\epsilon\) in the formula above. Discount gamma = 0.99 and GAE trace lmbda = 0.95 build the advantage. A small entropy bonus, 1e-4, keeps the policy from collapsing to one action too early. The device is a CUDA GPU when one is visible and the process was not started with fork.

10.5.2 Define an environment

The simulator is Gymnasium's inverted double pendulum, wrapped by TorchRL. ObservationNorm standardizes the observation using statistics gathered from 1,000 random steps. DoubleToFloat makes the dtype match the network. StepCounter records how long an episode lasts, which is the quantity you want to see grow: a balanced pendulum survives more steps. check_env_specs confirms the observation, reward, and action specs agree before any training, and a rollout of three steps is printed so you can see the TensorDict keys.

10.5.3 Policy

The actor is three tanh layers of width 256, then a linear map to twice the action dimension. NormalParamExtractor splits that vector into a location and a scale. ProbabilisticActor turns the pair into a TanhNormal squashed into the environment's action bounds, and it returns the log-probability. That log-probability is the numerator of \(r_t\). A reset TensorDict is passed through the policy once, before the collector exists, to force the lazy layers to materialize.

10.5.4 Value Network

The critic has the same three tanh layers and ends in a single linear unit. ValueOperator reads the observation key and writes a state value. PPO needs it twice: inside GAE, to form advantages, and inside the value loss, so the next batch's advantages are less wrong. Actor and critic do not share a trunk in this script.

10.5.5 Data Collector

SyncDataCollector rolls the policy out in the environment until it has frames_per_batch transitions, and stops after total_frames. split_trajs=False keeps the batch as one TensorDict rather than a list of episodes. Each iteration of the training loop is one of these batches. The collector, not the loss, is what talks to the pendulum.

10.5.6 Replay Buffer

The buffer stores one batch and no more: LazyTensorStorage(max_size=frames_per_batch) with SamplerWithoutReplacement. It is not a long-term replay memory of the DQN kind. PPO is on-policy. The buffer only shuffles the batch just collected so the inner loop can draw minibatches of 64 without repeating a transition inside one epoch.

10.5.7 Loss Function

ClipPPOLoss implements the clipped surrogate from the introduction, plus a value loss and an entropy bonus. Advantages come from GAE with the critic, averaged over the batch. The three pieces the training loop adds are loss_objective (the clipped policy term), loss_critic (smooth L1 on the value, coefficient 1), and loss_entropy. The clip is what stops a minibatch from dragging \(\pi_\theta\) far from the policy that collected the data.

10.5.8 Training Loop

For each collected batch the script recomputes advantages, flattens the TensorDict, and loads the buffer. Then, ten epochs of minibatches: evaluate the loss, sum the three terms, call backward, clip the gradient norm, and step Adam. A cosine schedule decays the learning rate to zero across the number of batches. Every tenth batch the policy is rolled out for 1,000 steps with ExplorationType.DETERMINISTIC, so the logged return is the mean action, not a sample. The progress bar prints the latest eval return, the training reward, the longest episode, and the learning rate.

10.5.9 Result

At the end the script plots four curves: average training reward, the longest training episode, the eval return, and the longest eval episode. On this pendulum the step count is the story. Early on the pole falls immediately. A run that is learning holds it up for more of the 1,000-step horizon, and the eval return climbs with that. Fifty thousand frames is a smoke test. If the curves are still noise, raise total_frames before changing the network.

10.5.10 Conslusion and Next Steps

PPO here is on-policy, clipped, and advantage-based. The previous chapter's DQN is off-policy and value-based; it replays old transitions, and this script throws each batch away after the inner epochs. The next chapter, function approximation, is what both of them rely on: a neural net standing in for a table of values or a table of action probabilities, which is the only way the pendulum's continuous state fits in memory.

10.5.11 Post-training

The same clipped update is how a language model is trained after pretraining. A person compares two answers, a reward model is fit to those comparisons, and PPO then raises the probability of answers the reward model scores higher. A KL penalty keeps the new policy from walking away from the pretrained model:

\(\max_\pi \mathbb{E}_{x, y \sim \pi}[r_\phi(x, y)] - \beta \,\mathrm{KL}(\pi(\cdot \mid x) \,\|\, \pi_{\mathrm{ref}}(\cdot \mid x))\)

Nathan Lambert's Reinforcement Learning from Human Feedback is the book for this stage. It is free to read and walks the whole post-training recipe: instruction tuning, the reward model, rejection sampling, PPO, and direct preference optimization. The pendulum script on this page is the same PPO step, with a scalar reward from the environment in place of \(r_\phi\).

RLCD (Reinforcement Learning from Contrastive Distillation) builds the preference pairs without a human rater. One prompt asks the model to follow a principle, another asks it to break that principle, and the two completions become a labeled pair. A preference model trained on those pairs supplies the reward, and PPO is the same update as above.
