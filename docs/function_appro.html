10.6 Function Approximation

Created Date: 2025-06-05

A table is the honest way to store an action value: one number for each state and action. CartPole's observation is four continuous numbers, and the inverted pendulum in the PPO chapter is continuous as well. The table does not fit. Function approximation replaces the table with a parameterized function, and in this book that function is a neural network.

10.6.1 From a table to a network

Write \(Q(s, a; \theta)\) for the network that stands in for the action-value table, and \(\pi(a|s; \theta)\) for a policy network. Learning is no longer "write down the new number." It is a gradient step on \(\theta\), the same step as every earlier chapter, with a reinforcement-learning loss in place of cross-entropy.

Two failures show up as soon as the table is gone. Nearby states share parameters, so an update that fixes one state moves the prediction at other states. And the training target itself moves, because it is built from the same network (DQN) or from the same policy (PPO). A frozen target network, a replay buffer, or a clipped probability ratio are three different ways of slowing that moving target down.

10.6.2 Where you already used it

DQN on CartPole is value-function approximation. The network maps an observation to two action values, and the loss is squared error against \(r + \gamma \max_{a'} Q(s', a'; \theta^-)\), with \(\theta^-\) a lagged copy of the weights. PPO on the double pendulum is policy approximation plus a second network for the state value. The clipped surrogate is what keeps the policy network from taking a step that the latest batch cannot justify.

There is no new script in this section. The approximators are the networks in simple_dqn.py and simple_ppo.py. What changes from supervised learning is the target, not the optimizer. The next chapter leaves reinforcement learning and extends PyTorch itself, starting with a custom operator around an ordinary Python function.
