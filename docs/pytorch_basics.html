2.3.1.1 Working With Data

PyTorch has two primitives to work with data: torch.utils.data.DataLoader and torch.utils.data.Dataset . Dataset stores the samples and their corresponding labels, and DataLoader wraps an iterable around the Dataset .

PyTorch offers domain-specific libraries such as TorchText, TorchVision, and TorchAudio, all of which include datasets. For this tutorial, we will be using a TorchVision dataset.

Every TorchVision Dataset includes two arguments: transform and target_transform to modify the samples and labels respectively.

from torchvision import datasets

training_data = datasets.MNIST(
    root='data',
    train=True,
    download=True,
    transform=torchvision.transforms.ToTensor(),
)

test_data = datasets.MNIST(
    root='data',
    train=False,
    download=True,
    transform=torchvision.transforms.ToTensor(),
)

We pass the Dataset as an argument to DataLoader. This wraps an iterable over our dataset, and supports automatic batching, sampling, shuffling and multiprocess data loading. Here we define a batch size of 64, i.e. each element in the dataloader iterable will return a batch of 64 features and labels.

batch_size = 64
train_dataloader = DataLoader(training_data, batch_size=batch_size)
test_dataloader = DataLoader(test_data, batch_size=batch_size)

for X, y in test_dataloader:
    print(f"Shape of X [N, C, H, W]: {X.shape}")
    print(f"Shape of y: {y.shape} {y.dtype}")
    break

2.3.1.2 Creating Models

To define a neural network in PyTorch, we create a class that inherits from nn.Module. We define the layers of the network in the __init__ function and specify how data will pass through the network in the forward function. To accelerate operations in the neural network, we move it to the accelerator such as CUDA, MPS, MTIA, or XPU. If the current accelerator is available, we will use it. Otherwise, we use the CPU.

device = torch.accelerator.current_accelerator().type \
    if torch.accelerator.is_available() else 'cpu'

print(f'Using {device} device')

class NeuralNetwork(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.flatten = torch.nn.Flatten()
        self.linear_relu_stack = torch.nn.Sequential(
            torch.nn.Linear(28 * 28, 512),
            torch.nn.ReLU(),
            torch.nn.Linear(512, 512),
            torch.nn.ReLU(),
            torch.nn.Linear(512, 10)
        )

    def forward(self, x):
        x = self.flatten(x)
        logits = self.linear_relu_stack(x)
        return logits

model = NeuralNetwork().to(device)
print(model)

2.3.1.3 Optimizing the Model Parameters

To train a model, we need a loss function and an optimizer.

loss_fn = torch.nn.CrossEntropyLoss()
optimizer = torch.optim.SGD(model.parameters(), lr=1e-3)

In a single training loop, the model makes predictions on the training dataset (fed to it in batches), and backpropagates the prediction error to adjust the model’s parameters.

def train(dataloader, model, loss_fn, optimizer):
    size = len(dataloader.dataset)
    model.train()
    for batch, (X, y) in enumerate(dataloader):
        X, y= X.to(device), y.to(device)

        # Compute prediction error.
        pred = model(X)
        loss = loss_fn(pred, y)

        # backpropagation
        loss.backward()
        optimizer.step()
        optimizer.zero_grad()

        if batch % 100 == 0:
            loss, current = loss.item(), (batch + 1) * len(X)
            print(f"loss: {loss:>7f}  [{current:>5d}/{size:>5d}]")

We also check the model’s performance against the test dataset to ensure it is learning.

def test(dataloader, model, loss_fn):
    size = len(dataloader.dataset)
    num_batches = len(dataloader)
    model.eval()
    test_loss, correct = 0, 0
    with torch.no_grad():
        for X, y in dataloader:
            X, y = X.to(device), y.to(device)
            pred = model(X)
            test_loss += loss_fn(pred, y).item()
            correct += (pred.argmax(1) == y).type(torch.float).sum().item()
    test_loss /= num_batches
    correct /= size
    print(f"Test Error: \n Accuracy: {(100*correct):>0.1f}%, Avg loss: {test_loss:>8f} \n")

The training process is conducted over several iterations (epochs). During each epoch, the model learns parameters to make better predictions. We print the model’s accuracy and loss at each epoch; we’d like to see the accuracy increase and the loss decrease with every epoch.

epochs = 20
for t in range(epochs):
    print(f"Epoch {t+1}\n-------------------------------")
    train(train_dataloader, model, loss_fn, optimizer)
    test(test_dataloader, model, loss_fn)
print("Done!")

2.3.2 Tensors

Tensors are a specialized data structure that are very similar to arrays and matrices. In PyTorch, we use tensors to encode the inputs and outputs of a model, as well as the model’s parameters.

Tensors are similar to NumPy’s ndarrays, except that tensors can run on GPUs or other hardware accelerators. In fact, tensors and NumPy arrays can often share the same underlying memory, eliminating the need to copy data (see Bridge with NumPy). Tensors are also optimized for automatic differentiation (we’ll see more about that later in the Autograd section). If you’re familiar with ndarrays, you’ll be right at home with the Tensor API. If not, follow along!

2.3.2.1 Initializing a Tensor

Tensors can be initialized in various ways. Take a look at the following examples in file demo_create.py .

The constructors used in this repo are in demo_create.py. It builds a rank-3 tensor from nested lists, then makes the same 2×2 numbers from a Python list and from a NumPy array. torch.tensor copies the data. torch.as_tensor on that array can share the buffer when the dtype and device already match.

Directly from Data

Tensors can be created directly from data. The data type is automatically inferred.

Nesting sets the rank. Two lists of length 2 become shape (2, 2), and integer entries stay an integer dtype until a later call asks for float. demo_create.py does the same with a longer nest and asserts the shape (3, 2, 5).

# directly from data
data = [[1, 2], [3, 4]]
x_data = torch.tensor(data)
assert x_data.shape == (2, 2)
From a NumPy array

Tensors can be created from NumPy arrays (and vice versa - see Bridge with NumPy).

torch.from_numpy shares the array's buffer, so a later write to the array shows up in the tensor. demo_create.py also calls torch.tensor on an array, which copies, and torch.as_tensor, which skips the copy when it can.

# from a numpy array
np_array = numpy.array(data)
x_np = torch.from_numpy(np_array)
assert x_np.shape == (2, 2)
From Another Tensor

The new tensor retains the properties (shape, datatype) of the argument tensor, unless explicitly overridden.

ones_like and rand_like read the shape off x_data so you do not retype it. The random call overrides dtype to float, which is what most layers expect even when the source tensor held integers.

x_ones = torch.ones_like(x_data)
print(f"Ones Tensor: \n {x_ones} \n")

x_rand = torch.rand_like(x_data, dtype=torch.float)
print(f"Random Tensor: \n {x_rand} \n")

shape is a tuple of tensor dimensions. In the functions below, it determines the dimensionality of the output tensor.

torch.rand draws uniform values on \([0, 1)\). ones and zeros fill masks and the starting point of a bias. demo_create.py also builds arange and linspace when the values should form a regular grid, and it seeds torch.manual_seed(47) before rand and randn so the draw repeats.

2.3.2.2 Attributes of a Tensor

Tensor attributes describe their shape, datatype, and the device on which they are stored.

Shape is the length of each axis, dtype is the storage format (float32 for torch.rand), and device stays cpu until you move the tensor. A matmul is legal only when the device matches and the contracting dimensions agree. demo_create.py also passes dtype and device into torch.tensor directly, choosing CUDA, MPS, or CPU from what the machine reports.

tensor = torch.rand(3,4)

print(f"Shape of tensor: {tensor.shape}")
print(f"Datatype of tensor: {tensor.dtype}")
print(f"Device tensor is stored on: {tensor.device}")

2.3.2.3 Operations on Tensors

Over 1200 tensor operations, including arithmetic, linear algebra, matrix manipulation (transposing, indexing, slicing), sampling and more are comprehensively described here .

A training step uses a short subset of that list: add a bias, multiply by a weight, index a batch, or reduce with sum and mean. The indexing patterns checked in this repo are in demo_indexing.py. demo_operate.py covers the elementwise arithmetic, broadcasting, reductions, and the shape ops view, transpose, squeeze, permute, and flatten.

Accelerator

Each of these operations can be run on the CPU and Accelerator such as CUDA, MPS, MTIA, or XPU.

By default, tensors are created on the CPU. We need to explicitly move tensors to the accelerator using .to method (after checking for accelerator availability). Keep in mind that copying large tensors across devices can be expensive in terms of time and memory!

# We move our tensor to the current accelerator if available
if torch.accelerator.is_available():
    tensor = tensor.to(torch.accelerator.current_accelerator())
print(f"Device tensor is stored on: {tensor.device}")
Device tensor is stored on: cuda:0
Standard MumPy-like Indexing and Slicing

Tensors use the same index and slice notation as NumPy. demo_indexing.py checks a 3×3 example: tensor2d[1, 2] is the entry in row 1, column 2, tensor2d[:, 1] is a whole column, and tensor2d[1:, 1:] is the bottom-right block. A negative index counts from the end, so tensor2d[-1, -1] is the last entry.

A boolean mask keeps the entries that pass a comparison: tensor1d > 25 selects the tail of [10, 20, 30, 40, 50]. Two integer tensors pick scattered coordinates, as in tensor2d[row_indices, col_indices]. The ellipsis fills any leading axes, so tensor3d[..., 0] matches tensor3d[:, :, 0].

torch.newaxis (and None) inserts a length-1 axis. The script asserts that a vector of shape (3,) becomes a column of shape (3, 1). A 0-d or one-element tensor gives up its Python number through .item().

2.3.3 Datasets and DataLoaders

Code for processing data samples can get messy and hard to maintain; we ideally want our dataset code to be decoupled from our model training code for better readability and modularity. PyTorch provides two data primitives: torch.utils.data.DataLoader and torch.utils.data.Dataset that allow you to use pre-loaded datasets as well as your own data. Dataset stores the samples and their corresponding labels, and DataLoader wraps an iterable around the Dataset to enable easy access to the samples.

PyTorch domain libraries provide a number of pre-loaded datasets (such as FashionMNIST) that subclass torch.utils.data.Dataset and implement functions specific to the particular data. They can be used to prototype and benchmark your model. You can find them here: Image Datasets, Text Datasets, and Audio Datasets

2.3.3.1 Loading a Dataset

demo_quick_start.py loads MNIST through torchvision.datasets.MNIST. train=True is the 60,000 training digits and train=False is the 10,000 test digits. download=True fetches the files into the data directory on the first run.

Each split is constructed with transform=torchvision.transforms.ToTensor(). That turns a PIL digit into a float tensor on \([0, 1]\) with shape (1, 28, 28). The label stays a class index from 0 to 9.

2.3.3.2 Iterating and Visualizing the Dataset

The same script wraps each split in a DataLoader with batch_size = 64. One iteration yields a pair (X, y). X has shape [64, 1, 28, 28] (batch, channel, height, width) and y has shape [64] with dtype int64.

The loop prints that one test batch and then breaks. It is a layout check, not a plot. The quickstart listing higher on this page shows the same printout.

2.3.3.3 Creating a Custom Dataset

demo_quick_start.py does not declare its own Dataset. It uses the torchvision MNIST class, which already implements __len__ and __getitem__. A custom dataset is that same pair of methods: store the samples, and return (feature, label) from __getitem__ so DataLoader can batch them.

The worked custom set in this repo is CustomImageFolder in flower_conv_mlp.py. It walks class subfolders, records an image path and an integer label for each file, and applies transform inside __getitem__ after opening the image as RGB.

2.3.4 Transforms

A transform is a callable that runs on one sample before the loader batches it. In demo_quick_start.py the only transform is ToTensor, so every MNIST digit arrives as a float tensor.

Several steps go in a torchvision.transforms.Compose list. flower_conv_mlp.py uses one list for training: resize to 150×150, a random horizontal flip, a rotation of 30 degrees, color jitter, a small affine shift, then ToTensor. The validation list is only resize and ToTensor, so evaluation is not randomly augmented. The CIFAR-10 loader in simple_distillation.py is a third example: ToTensor followed by Normalize with the usual RGB mean and standard deviation.

2.3.5 Build the Nerual Model

Section 2.3.1.2 already shows NeuralNetwork from demo_quick_start.py. forward flattens 28×28 to 784, then a sequential stack applies a linear layer to 512, ReLU, another linear layer to 512, ReLU, and a linear layer to 10 logits. The script constructs that class and moves it with .to(device), where the device is the current accelerator or CPU.

The same file also defines ConvNeuralNetwork: two 3×3 convolutions (1→32 and 32→64), each followed by ReLU and 2×2 max-pooling, then a linear head from 64 * 7 * 7 to 128 and on to 10. The training run instantiates the fully connected NeuralNetwork, not the conv net. Calling model(X) runs forward; the training loop does not call forward by name. Printing the module lists each layer's in and out features so the 784 input size can be checked before the first step.

2.3.6 Automatic Differentiation

When training neural networks, the most frequently used algorithm is back propagation. In this algorithm, parameters (model weights) are adjusted according to the gradient of the loss function with respect to the given parameter.

To compute those gradients, PyTorch has a built-in differentiation engine called torch.autograd. It supports automatic computation of gradient for any computational graph.

Consider the simplest one-layer neural network, with input x, parameters w and b, and some loss function. It can be defined in PyTorch in the following manner:

# input tensor
x = torch.ones(5)
# expected output
y = torch.zeros(3)
w = torch.randn(5, 3, requires_grad=True)
b = torch.randn(3, requires_grad=True)
z = torch.matmul(x, w) + b
loss = torch.nn.functional.binary_cross_entropy_with_logits(z, y)

2.3.7 Optimization Model Parameters

The update rule in demo_quick_start.py is SGD with learning rate 1e-3 on model.parameters(). The loss is CrossEntropyLoss on the 10 logits and the integer digit labels. The listing in section 2.3.1.3 is this same loop.

train calls model.train(), moves the batch onto the model device, then optimizer.zero_grad(), the forward pass, loss.backward(), and optimizer.step(). Every 100 batches it prints the loss and how many samples have been seen. test calls model.eval(), wraps the pass in torch.no_grad(), and reports accuracy from pred.argmax(1) together with the average loss. The script runs that pair for 20 epochs.

2.3.8 Save and Load Model

demo_quick_start.py keeps the trained weights in memory and ends at the last test print. To keep them, save the state dict, which is the tensors only:

torch.save(model.state_dict(), 'mnist_fc.pth')

reloaded = NeuralNetwork().to(device)
reloaded.load_state_dict(torch.load('mnist_fc.pth', weights_only=True))
reloaded.eval()

A full torch.save(model, path) pickles the module object instead. That is what flower_conv_mlp.py does with flower_conv_mlp.pth after training convmlp_s. It loads the object back with weights_only=False, moves it to the device, calls eval, and scores three flower photos.
